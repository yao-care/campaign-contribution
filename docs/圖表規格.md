# 政治獻金指南 — 圖表規格

> 對照 `docs/建站規格.md` 撰寫。撰寫日期 2026-08-30。
> 所有配色均以驗證器實測，非目測判斷。

---

## 0. 兩個先決條件

### 0.1 D3 只在建置期跑，產出靜態 SVG

**不是** client-side 渲染。理由來自建站規格自己的三條硬性要求：

| 規格條文 | 對圖表的意涵 |
|---|---|
| §1「所有答案必須存在於 HTML 中」 | AI 爬蟲多數不執行 JavaScript。圖表若由前端繪製，等於不存在 |
| §1「島嶼式，僅工具頁需要；其餘頁面零 JS」 | 法條頁、選舉類別頁、政黨頁都不得載入 D3 執行檔 |
| §10.2「TTFB < 500ms」 | 8,445 頁各塞一份 D3 bundle 不可行 |

做法：把 D3 當**數學函式庫**用，不用它的 DOM 操作。

```
可用：d3-scale、d3-array、d3-shape、d3-format、d3-time-format
不用：d3-selection、d3-transition、d3-zoom（需要瀏覽器 DOM）
```

在 `.astro` 的 frontmatter 呼叫 d3 算出座標與路徑，模板直接輸出 `<svg>` 標籤。
產出是純標記，沒有執行期相依，與現有的零 JS 架構一致。

### 0.2 每張圖都必須有對應的 `<table>`

現有的統計區塊已經都有表格，圖表是**加在表格旁邊**，不是取代它。三個理由：

- §9.2「數字用真 `<table>` 加 `<th>`，不用 div 模擬」——AI 引擎靠表格取數
- §11 無障礙 AA：SVG 圖表對螢幕閱讀器等於空白，表格才是可及的資料來源
- 圖表配色若對比不足，規範允許以「可見標籤或表格檢視」補救；我們本來就有

## 1. 配色：單色序列為主，不用類別色

### 1.1 為什麼不用類別色

建站規格 §7 明訂配色刻意避開**藍、綠、白、橘**等政黨識別色。這使得標準類別色盤幾乎無解——實測結果：

| 候選 | 結果 |
|---|---|
| 朱紅＋石板青（現有 token） | ❌ 彩度地板不過，石板青彩度僅 0.041–0.09，讀起來是灰色 |
| 朱紅＋石板青（提高彩度） | 彩度過關，但青色逼近民眾黨識別色，違反 §7 |
| 朱紅＋石板青＋暗琥珀 | ❌ 兩色彩度都不足；提高後同樣撞政黨色 |

**解法：改用單色序列與強調。** 本站的資料職務幾乎都是「比大小」與「趨勢」，不是「辨識身分」——依照選型原則，序列色本來就是安全預設，類別色只在「系列本身就是主題」時才該用。這同時解掉政黨色衝突。

### 1.2 已驗證通過的四組色

以 `validate_palette.js` 實測，全部六項檢查通過。

**單色序列（六階，用於長條圖、直方圖、熱區圖）**

```
light  #f19f92  #e47d6f  #d15d4f  #c03e32  #a71b14  #830e09
dark   #85362d  #ab4237  #ce5245  #e86e5e  #f98f81  #ffb3a7
```

light 通過：亮度單調、相鄰 ΔL ≥ 0.06、淺端對比 ≥ 2:1、單一色相（色相跨度 1°）。
dark 為**另行選階**，不是 light 的翻轉——暗色模式的亮度帶是 L 0.48–0.67，比 light 的 0.43–0.77 窄。

**雙階（收入／支出對照，同色深淺）**

```
light  #d86f61（淺）  #a52018（深）
dark   #e16856（淺）  #b02114（深）
```

light 六項全過（CVD ΔE 18.7、常規視覺 ΔE 19.3、對比 ≥ 3:1）。
dark 六項全過。

收入／支出用同色深淺而非兩個色相，是選型原則裡「before → after per item」的 dumbbell 做法，
既避開政黨色，也不會讓讀者以為兩者是不同「身分」。

### 1.3 其他規則

- 文字一律用 `--ink`／`--ink-2`／`--muted`，**不用系列色**；顏色只上在圖形上
- 網格與座標軸用 `--rule`，保持退讓
- 兩個系列以上一定有圖例，且四個以內同時直接標註
- 絕不使用雙 Y 軸。單位不同就分成兩張圖

## 3. 要動到資料層的部分

### 3.1 罰則需要結構化欄位

`src/data/penalties.ts` 的 `sanction` 目前是自由文字：

```
sanction: '處 3 年以下有期徒刑，得併科新臺幣 20 萬元以上 100 萬元以下罰金。'
```

要畫範圍長條，需另加結構化欄位（自由文字保留給頁面顯示）：

```ts
fine?: { min: number; max: number };      // 罰鍰範圍（元）
prison?: { maxYears: number };             // 自由刑上限
multiplier?: { value: number; of: '收受金額' | '捐贈金額' };
```

三種單位不能放同一軸，要分成三張小圖或只做罰鍰那張。

### 3.2 抵稅曲線需要在建置期取樣

`DEDUCTION` 只有 `ratio` 與 `cap` 兩個數字。折線圖要在建置期沿所得軸取樣算出可扣除額，
轉折點（`cap / ratio`，個人為 100 萬元、營利事業為 500 萬元）必須是取樣點之一，否則拐角會被畫圓。

### 3.3 直方圖的分組

`reportIncomes` 已排序落地。分組寬度不要用等寬——收入分布極度右偏（村里長 n=479，
範圍 1 元至 87 萬元）。建議用**對數分組或分位數分組**，並在圖說標明分組方式。

## 5. 驗收條件

- 每張圖旁必有 `<table>`，且表格內容與圖表一致
- 圖表為建置期產出的 inline SVG，頁面無任何執行期 JS 相依
- 色票以 `validate_palette.js` 實測通過，light 與 dark 各自驗過
- SVG 有 `role="img"` 與 `<title>`；`aria-describedby` 指向對應表格
- 窄螢幕下圖表不溢出，與 `.table-scroll` 同樣可橫向捲動且可鍵盤聚焦
- 圖表全部關閉後，頁面資訊不減損（表格仍在）
